# Statistical Analysis of Query Response Time under Database Indexing Using R

## Project aim

This project investigates whether database indexing reduces the response time
of an equality-search query. PostgreSQL was used to create benchmark tables
and R was used to collect, analyse, visualise, and test the real timing data.

## Experimental design

- Database: PostgreSQL on localhost
- Database name: `indexing_project`
- Table sizes: 10,000, 100,000, and 500,000 rows
- Search methods: No index, B+ tree, and Hash
- PostgreSQL implementation: `btree` is used as the practical B+ tree index
- Query type: equality lookup using `WHERE lookup_key = ...`
- Repetitions: 30 measurements per condition
- Total observed timings: 3 sizes x 3 methods x 30 = 270

## Main result

The real benchmark data showed that indexed equality searches were much faster
than no-index searches, especially as table size increased.

At 500,000 rows:

- No index mean response time: 71.074 ms
- B+ tree mean response time: 1.767 ms
- Hash mean response time: 1.670 ms
- B+ tree was approximately 40 times faster than no index
- Hash was approximately 42 times faster than no index

The paired statistical tests found strong evidence that both indexed methods
were faster than no index. This experiment did not find a statistically
significant difference between B+ tree and Hash for the tested equality lookup.

## R scripts

The experiment has already been run, so the saved CSV, results, and graphs can
be inspected without rerunning the database benchmark.

### Core workflow

1. `00_Setup.R` - creates/checks the project folders
2. `01_collect_timings.R` - connects to PostgreSQL and collects 270 real timings
3. `02_exploratory_analysis.R` - calculates descriptive statistics and graphs
4. `04_hypothesis_tests.R` - contains the paired comparisons used to test indexing
5. `05_final_summary.R` - creates the final result tables, graph, and conclusion
6. `08_project_validation.R` - checks the dataset and required project files

### Optional syllabus analysis

- `03_distribution_fits.R` explores Exponential, Gamma, and Weibull models.
- `04_hypothesis_tests.R` also contains ANOVA, regression, and exploratory
  chi-square analysis. These are supporting analyses; the main conclusion uses
  descriptive statistics, speed-up, and paired comparisons.

Do not rerun `01_collect_timings.R` merely to view the results. Rerunning it
creates a new set of timings, which can differ slightly with system activity.

## Execution-plan verification

PostgreSQL execution plans were checked using `EXPLAIN (ANALYZE, BUFFERS)`.

- No-index table showed `Seq Scan`
- B+ tree table showed `Index Scan using ..._bplus_lookup_idx`
- Hash table showed `Index Scan using ..._hash_lookup_idx`

This confirms that the three benchmark conditions used the intended
database search approaches.

## Important limitations

- Timings can be affected by caching, operating-system activity, and background programs.
- This benchmark tested equality searches only.
- Hash indexes are not suitable for range-query comparisons.
- Query timings were right-skewed, so log-transformed paired tests were used
  as important supporting evidence.
- Results apply to this computer, PostgreSQL version, and benchmark design.
